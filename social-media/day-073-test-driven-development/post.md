Day 73 of 365 Days of AI — Test-Driven Development

Work test-first: state the red-green-refactor loop precisely, write one small failing test at a time and read its failure to confirm it failed for the reason you predicted, write the least code that turns it green, refactor against a safety net and prove the count did not move, use triangulation and fake-it-till-you-make-it deliberately rather than as theatre, break your own code on purpose to test a test that has never been red, and judge honestly which code is worth driving test-first and which is not.

What today covers:
→ State the red-green-refactor loop precisely
→ Explain why watching a test fail is the only moment at which evidence exists that the test is wired to the behaviour it names
→ Read a pytest failure well enough to distinguish a right-reason red (a missing name

The lab is the point: 30 minutes of hands-on work you run yourself, offline, with output you can check against a real captured run.
