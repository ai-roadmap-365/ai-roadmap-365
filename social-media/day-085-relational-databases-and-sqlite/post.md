Day 85 of 365 Days of AI — Relational Databases and SQLite

Say precisely why a JSON file stops being an adequate store — measured in bytes rewritten, constraints absent, updates lost and scans repeated — and replace it with a real database: a schema whose primary keys, foreign keys, NOT NULL, UNIQUE and CHECK constraints the engine enforces on every write from every program.

What today covers:
→ Measure rather than assert the four points at which a JSON file stops paying
→ Define the relational model precisely: a relation as a set of tuples
→ Write a schema as a promise the engine keeps

The lab is the point: 30 minutes of hands-on work you run yourself, offline, with output you can check against a real captured run.
