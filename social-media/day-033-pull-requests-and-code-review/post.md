Day 33 of 365 Days of AI — Pull Requests and Code Review

Explain the pull-request and code-review workflow end to end — propose a change on a branch, open a PR, review and iterate, choose a merge strategy, and protect a branch — and rehearse the whole loop locally with plain Git.

What today covers:
→ Describe the pull-request (merge-request) model and explain why teams route every change to shared code through it instead of pushing directly to main
→ Name the parts of a pull request page
→ Write the anatomy of a good pull request: small

The lab is the point: 30 minutes of hands-on work you run yourself, offline, with output you can check against a real captured run.
