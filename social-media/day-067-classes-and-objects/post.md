Day 67 of 365 Days of AI — Classes and Objects

Replace a dictionary plus a pile of functions that assume its keys with a class that binds state to the behaviour maintaining its invariants: you will write __init__, self, methods, staticmethods and classmethods knowing exactly what each receives, defend a rule with a @property that rejects an invalid value, give every class a __repr__ that makes debugging possible, avoid the shared-mutable-class-attribute bug, decide honestly whether a class is even the right tool, and build a minimal object system from dicts and closures so you can see that a class is a dictionary of state plus a dictionary of functions with syntax on top.

What today covers:
→ Explain the problem a class solves
→ Distinguish a class (the blueprint) from an instance (a concrete thing with its own state)
→ Explain why __init__ is an initializer and not a constructor

The lab is the point: 30 minutes of hands-on work you run yourself, offline, with output you can check against a real captured run.
